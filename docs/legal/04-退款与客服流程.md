# 退款与客服流程(框架草案 · G8)

## 1. 范围
- 对象商品:**风险筛查报告(単発購入)** 及后续订阅(如启用)。
- 原则:数字内容在**交付开始后**原则不退款(与特商法表記一致);下列情形**全额退款**:

| 情形 | 判定 | 时限 |
|---|---|---|
| 重复扣款 / 系统错误多收 | 立即全额退 | 确认后 3 工作日内发起 |
| 支付成功但**报告未交付**且 24 小时内未修复 | 全额退 | 同上 |
| 同一交易被重复计费(用户举证) | 全额退 | 同上 |
| 已交付后"主观不满意" | 原则不退;可给**一次性客户关怀额度**(如赠 1 次查询) | 7 日内答复 |

## 2. 客服渠道

- 渠道:【Email 优先】+ 【页面内表单】;工作时段【 】(JST);我们会在收到后尽快对应。
- 涉及支付问题或个人信息泄露风险时,按 APPI 要求判断并向個人情報保護委員会报告,必要时**72 小时内**向用户告知。

## 3. 流程
1. 受理(记录工单:时间/账号/订单号/诉求)→ 2. 核验(`payment_orders` 状态、webhook 记录、报告交付记录)→ 3. 判定(上表)→ 4. 执行(Stripe 退款,记录到工单)→ 5. 回访 + 归档。

## 4. 内部要求
- **不得**要求用户提供卡号/CVC;退款不得手工改动 `usage_events`(append-only,只能新增记录)。
- 每笔退款须留存:订单号、金额、原因、批准人、Stripe refund id。
