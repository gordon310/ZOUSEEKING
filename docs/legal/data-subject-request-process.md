# 数据主体请求（DSAR）流程

**适用版本：** `privacy-2026-08`  这是离线运营流程，不是已承诺的法定期限或法律意见。

## 1. 入口和受理

用户从 [客服入口](../../web/support.html) 发起查阅、更正、删除、限制处理、反对、撤回可选同意或可携带副本请求。当前 `support@zouseeking.example` 为 `.example` 保留域名，不发送邮件；上线前必须由运营主体替换为受控工单系统。网页不会收集或提交真实个人资料。

受理人生成随机工单 ID，只保存政策版本、请求类型、范围摘要、请求时间和状态。不要在日志或聊天工具中复制邮箱、姓名、房产地址、附件、token 或完整请求正文。

## 2. 身份和范围

在披露任何资料前，用当前已认证会话、Auth 邮箱确认或其他经法务批准的最小验证方法确认请求人。不能仅凭客户端提交的 email 认定所有权；不确定时统一返回“需要补充验证”，不要透露账户是否存在。代理人请求需要记录授权范围和有效期。

确认请求范围：账户身份、profile、项目/文件、查询/报告、同意证据、客服/事故记录、公开数据副本，或仅撤回某一用途。区分用户资料、第三方个人资料、公开数据、`modeled_estimate` 和 `synthetic_fixture`，不把它们混为一份导出。

## 3. 处理和时间线

内部目标如下，计时从完成必要验证开始：

1. **24 小时**内确认收到、说明范围和预计下一步；
2. 普通查阅/可携带副本在 **30 天**内提供受限导出或说明合法延期；
3. 更正先冻结待改字段、保留原始证据和修订版本，再由用户/人工确认；
4. 删除请求按账户删除流程撤销会话并删除/匿名化主数据，备份最多 **90 天**自然到期；
5. 法律保留、争议、欺诈调查、财务或他人权利需要限制删除时，说明受限字段、依据、复核日期和解除后动作；
6. 不能验证、找不到记录或资料已匿名化时，使用统一说明，不泄露其他人的记录。

## 4. 导出和更正质量

导出使用结构化 JSON/CSV，附上字段含义、单位、数据类别、来源期间、生成版本、样本量、缺失值和限制；不要从 `约3,450万日元` 等 presentation string 反推数字。公开数据与用户资料分开，禁止加入无关用户或后台成员。

更正必须记录旧值的证据定位、新值、确认人、时间和版本；不能覆盖不可变原始快照。若请求涉及法律、税务或投资结论，只提供数据事实和风险边界，不代替专业意见。

## 5. 关闭和复核

工单完成后记录结果代码、主数据删除/匿名化计数、对象删除结果、备份批次、例外和复核人。请求人可以通过同一受控入口追问或投诉。运营负责人每月抽查 SLA、越权访问、失败重试和最小化情况；本仓库没有线上工单或真实用户请求，测试只使用 synthetic fixture。
