# 隐私与账户运营 Runbook（离线版）

**policy_version:** `privacy-2026-08`
**terms_version:** `terms-2026-08`
**环境状态：** 离线契约；`migration_baseline_status = reconciliation_required`
**禁止动作：** 未取得单独授权不得连接/写入线上数据库、Auth、RLS、Storage、部署、DNS、billing，不得发送邮件或站内通知。

## 1. 角色和证据

正式上线前须指定运营负责人、隐私负责人、值班工程师、客服负责人、法务联系人和备份恢复负责人。当前仓库没有真实姓名或真实联系方式。每个请求只记录不可预测的工单 ID、状态、时间、政策版本、处理角色、范围摘要和结果代码；日志不记录邮箱、姓名、令牌、原始上传内容或完整错误。

可审计证据包括：注册同意 metadata、独立定位同意版本、删除/DSAR 时间线、Auth 会话撤销结果、受限访问审计、Storage 删除结果、备份轮换批次、事故通知决定和复核人。证据本身也受最小化和保留政策约束。

## 2. 资料保留和删除 SLA

这些是内部目标，不是已执行的生产承诺：

| 事件 | 目标 | 完成证据 |
| --- | --- | --- |
| 收到账户删除或 DSAR | **24 小时**内确认收到并生成工单 ID | 工单状态、政策版本、确认时间（不含邮箱正文） |
| 限制账户访问和撤销会话 | **24 小时**内开始处理 | Auth 撤销结果、FastAPI 授权拒绝结果 |
| 主库 profile、项目、查询、报告和私有对象 | **30 天**内删除或不可逆匿名化 | 受限删除清单、行数/对象计数、失败分类 |
| 备份副本 | 主库删除后最多 **90 天**自然到期 | 备份批次和轮换记录；不直接修改线上备份 |
| 未转正匿名 intake | 24 小时到期，清理窗口最多再延 5 分钟 | 会话状态、Storage 对象删除路径 |

SLA 计时从完成必要身份验证开始。法律保留、争议、欺诈调查或财务义务需要记录例外范围、依据、复核日和解除后的补删动作。Render Free 休眠会让机会式清理无法保证墙钟 SLA；若产品承诺严格期限，必须先配置持续运行并经过演练的清理器。

## 3. 账户删除流程

1. 用户在账户页勾选确认并提交 `POST /api/account/deletion-request`；请求只包含当前政策版本、条款版本和固定确认值 `DELETE_ACCOUNT`。
2. FastAPI 验证 Supabase bearer 身份、当前版本和确认值；不能用客户端 email 作为所有权边界。
3. 未配置受信任删除执行器时返回 503：`no account data was changed`，页面明确提示客服入口，不得显示“已删除”。
4. 未来执行器获批后，先撤销会话/阻止新任务，再按依赖顺序删除 Storage、项目/查询/报告、profile 和可选索引；审计记录只保留最小删除证明。
5. 依赖外部 Auth Admin、RLS、Storage、备份或队列的动作，必须在单独的 migration baseline、backup/restore 和回滚方案通过后执行；本仓库当前不执行。
6. 完成或失败都通过受限工单记录状态、时间、失败类别和复核人，不在公开 API 暴露内部异常。

删除账户不等于取消订阅、撤回第三方复制件或删除依法必须保留的记录；客服须向用户说明边界。

## 4. 密码、登录、登出和撤销

- 注册使用 Supabase Auth；当前前端会在提交时生成 `consent_at`，不得让用户在输入框填写。
- 找回密码使用 Supabase `/recover`，对已存在和不存在邮箱返回统一成功文案，不显示账户是否存在；邮件供应商、频率限制和 redirect allowlist 需在上线前核验。
- 注册、登录、找回密码和删除申请必须由受信任服务端按账户与滥用来源双维度限流；当前静态前端不能提供该控制，尚未完成验证。
- 修改密码需要已认证会话和二次确认；成功后应按 Supabase 配置验证其他 refresh token 是否失效，并提示用户重新登录仍有效的设备。
- 登出尽力调用 Supabase `/logout` 撤销当前会话；远端令牌已过期时仍清理本地 UI。任何 token 不得进入 URL、日志或客服工单。
- 当前静态 local fallback 会将演示会话/token 放在 browser storage，是既有 release blocker；迁移到受信任、HttpOnly 会话前不得声称认证安全。

## 5. 客服和资料主体请求

客服入口为静态 [support.html](../../web/support.html)，当前保留邮箱 `support@zouseeking.example` 仅作占位，不会发送通知。收到请求后按 [DSAR 流程](data-subject-request-process.md)验证身份、拆分查阅/更正/删除/限制/反对/可携带副本，并使用 24 小时确认、30 天完成或说明延期的内部目标。

客服不能索取完整密码、refresh token、银行卡、身份证件全文或无关家庭成员资料。导出前再次确认范围和接收渠道，下载链接应短期、受限且可撤销。

## 6. 监控、演练和发布门槛

每日/每周只看脱敏指标：删除请求年龄分布、失败分类、匿名对象过期数、Auth 撤销失败数、备份轮换年龄、DSAR SLA 越界和事故响应时间。禁止用客户行、邮箱或原始 payload 做报表。

上线前必须完成：运营主体/法务确认、Auth Admin 删除演练、RLS 四类身份测试、Storage 私有对象删除演练、fresh migration reset、backup/restore 与 forward-fix、持续清理器、客服工单权限、事故桌面演练和部署批准。当前均未在本任务执行；见 `AGENTS.md` 的 release blockers。
