# MLIT XIT001 API Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Switch the MLIT transaction importer to the official XIT001 API while preserving CSV fallback, provenance, numeric analytics, and local end-to-end verification.

**Architecture:** Keep the existing normalization and PostgreSQL contract, add an XIT001 response adapter with gzip/404 handling, and select API or CSV through `--source`. API requests are one prefecture at a time, sequential, and rate-limited; the API key is read only from `MLIT_API_KEY` and never included in output or persisted.

**Tech Stack:** Python standard library `urllib`, `gzip`, `json`, `csv`, `zipfile`; asyncpg; pytest; PostgreSQL disposable database; local HTTP fixture server.

**Spec:** `/tmp/zouseeking-mlit-api-task.md`

## Global Constraints

- Use `backend/.venv/bin/python` for every Python command.
- Never call the obsolete `api-aur` endpoint.
- Never print, write, log, or fixture the API key.
- API scope is prefectures `13,27,15`, years `2025,2026`, quarters `1..4`, serial with at least 2 seconds between requests.
- HTTP 404 and empty data are successful no-data outcomes.
- No production database, deployment, SSH, commit, or push.
- Detailed evidence goes to `/tmp/zouseeking-mlit-api-details.md`.
