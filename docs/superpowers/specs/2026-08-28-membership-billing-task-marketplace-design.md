# 小象避坑／小象数据 V1 会员、计费与任务协作设计规格

**状态：** 产品规则已确认；架构采用 ADR-0001；前端界面与示例报告内容已验收（2026-08-29）

[ADR-0001：权威后端与 schema 所有权](../../architecture/adr-0001-authoritative-backend-and-schema.md)

**日期：** 2026-08-28

**首发地区：** 中国大陆、香港、澳门、台湾

**统一计费时区：** UTC+8

## 1. 目标

为“小象避坑”和“小象数据”定义第一版可实施的账户、机构、套餐、额度、任务协作、隐私授权、退款和后台权限规则。

本设计必须做到：

- 区分身份、套餐、权益、机构角色、合作方资格和内部后台权限。
- 免费查询、单份报告、包月权益和机构数据服务均有明确边界。
- 额度扣减原子、幂等、可审计，失败不会重复扣量。
- 任务池只负责撮合，不替 C、B 双方定价、收款或结算。
- 客户邮箱只有在任务匹配且双方分别同意后才能交换。
- 自动续费、取消、退款、报告失败和价格调整规则透明且一致。
- 数据来源、数据类别、更新时间、样本量和限制继续遵守项目的数据真实性要求。

## 2. 非目标

V1 不包含：

- 公共数据 API。
- 自动超额扣费。
- 预付钱包、可提现余额或跨月额度结转。
- 任务竞价、平台定价、佣金、托管支付、发票或任务款退款。
- 站内实时聊天或邮件中继。
- 一个任务同时匹配多个 B 端机构。
- 按每日汇率自动调整本地价格。
- 仅靠前端页面、查询参数或隐藏入口实现授权。
- 同时扩展 Supabase、FastAPI、Edge Function 和本地 worker 为新的平行会员后端。

## 3. 核心模型

### 3.1 分层原则

系统不得使用一个互斥的全局 `role` 或不断扩张的 `membership_tier` 字符串承载全部业务。

| 层 | 回答的问题 | V1 示例 |
| --- | --- | --- |
| 登录身份 | 谁在操作 | 一个经过验证的自然人账户 |
| 产品入口 | 用户在使用什么 | 小象避坑、小象数据 |
| 机构归属 | 用户代表哪个组织 | B 端机构及其成员 |
| 套餐 | 谁购买了什么 | 个人 C Plus、机构 B Data Pro |
| 权益 | 当前允许执行什么 | 查询、报告、分析、订阅、导出 |
| 合作方资格 | 是否允许申请任务 | 已认证服务合作方 |
| 内部角色 | 工作人员可以管理什么 | 数据运维、审核、财务等 |

同一自然人可以同时：

- 使用 C 端个人功能；
- 加入一个或多个 B 端机构；
- 代表通过认证的机构申请任务；
- 在单独授权后承担内部工作人员职责。

商业套餐不能授予内部后台权限。

### 3.2 账户与机构

- C 端套餐属于个人账户。
- B Data Pro 属于机构。
- 一个 B 端机构最多有 5 个活跃成员，包含机构所有者。
- V1 只设置两种机构角色：
  - `owner`：管理成员、套餐、账单和机构资料。
  - `member`：使用机构共享的数据权益。
- B 端查询、统计、订阅和导出额度均由机构共享，不按成员重复发放。
- 机构申请任务时指定一名负责成员；任务申请归机构所有，不归个人所有。
- 只有机构所有者和任务负责成员可以访问匹配后的客户联系信息。

### 3.3 认证服务合作方

- “认证服务合作方”是机构状态，不是付费套餐。
- 购买 B Data Pro 不会自动获得任务申请资格。
- 未购买 B Data Pro 的机构也可以申请合作方认证。
- 只有审核通过且状态为有效的机构可以申请任务。
- 合作方暂停或终止后不能提交新申请，但必须保留已有任务和审计记录的受限访问，直到任务依法关闭。

## 4. 产品与套餐

### 4.1 小象避坑

| 套餐 | 基础查询 | 完整报告 | 统计订阅 |
| --- | ---: | ---: | ---: |
| Free | 每日 3 次 | 按份购买 | 无 |
| 单份报告 | 包含该物件所需查询 | 1 份 | 无 |
| C Plus | 每自然月 100 次 | 每自然月 12 份 | 最多 3 个有效订阅 |

已确认参考价格：

| 产品 | CNY | JPY | USD |
| --- | ---: | ---: | ---: |
| 单份报告 | 5 | 100 | 0.99 |
| C Plus／月 | 49 | 990 | 9.9 |

规则：

- 单份产品应称为“标准风险筛查报告”，不得宣传为人工尽调、法律意见或收益保证。
- C Plus 的 12 份报告和 100 次查询不结转。
- 超过 12 份后，用户可以主动按单份报告价格购买；不得自动扣费。
- Free 的每日查询额度在 UTC+8 每日 00:00 重置，不结转。
- 基础查询达到 100 次后停止新增查询；购买单份报告时允许完成该物件所需的一次查询，且不再额外消耗基础查询额度。
- 一个统计订阅是一个有效条件组合，例如“东京都港区＋公寓＋出售”。
- 删除统计订阅后立即释放名额。
- 邮件发送失败和系统重试不会增加订阅槽位或重复计量。

### 4.2 小象数据

| 套餐 | 基础数据查询 | 统计分析 | 统计订阅 | 导出 |
| --- | ---: | ---: | ---: | ---: |
| B Free | 每月 30 次 | 每月 5 次 | 无 | 无 |
| B Data Pro | 每月 500 次 | 每月 100 次 | 10 个有效订阅 | 每月 10,000 行 |

已确认参考价格：

| 产品 | CNY | JPY | USD |
| --- | ---: | ---: | ---: |
| B Data Pro／月 | 199 | 3,999 | 39.9 |

规则：

- B Data Pro 包含最多 5 个活跃机构成员。
- 全部额度由机构成员共享。
- V1 不开放公共 API。
- 达到额度后停止新增付费操作，显示已用量、剩余量、重置时间和联系支持入口。
- V1 不自动售卖 B 端流量包。
- 后台可以基于合理业务需要授予有期限的临时额度，必须记录原因、操作者和到期时间。
- 首发默认额度运行两个完整自然月后再评估。
- 当前计费期内不能下调已购买额度；未来下调必须按重大不利变更处理。

### 4.3 本地价格

- 价格表支持 `CNY`、`HKD`、`TWD`、`MOP`、`JPY` 和 `USD`。
- 首发收款前，财务必须为对应账单地区启用经过批准的本地价格。
- 没有有效本地价格的地区不得接受付款，也不得临时进行客户端汇率换算。
- 本地价格独立版本化，不按每日汇率自动浮动。
- 价格由经过验证的账单地区决定，不能只靠切换界面币种购买其他地区价格。
- 所有页面明确显示币种、税费口径和最终支付金额。

## 5. 计费周期与首月折算

### 5.1 自然月

- 所有首发地区统一使用 UTC+8。
- 完整计费期为每月 1 日 00:00（含）至次月 1 日 00:00（不含）。
- 额度在次月 1 日 00:00 重置，不在月末最后一天 00:00 提前重置。
- 未使用额度不结转。

### 5.2 首月折算

- 首月价格和额度按购买日到当月最后一天的剩余日历天数折算，购买日计入剩余天数。
- 价格折算公式：`完整月价格 × 剩余日历天数 ÷ 当月总天数`。
- 金额按支付币种的最小单位舍入。
- 查询、报告、统计、订阅槽位和导出行数按相同比例计算并向上取整。
- C Plus 首月最低收费不得低于当地单份报告价格，防止月底以低于单份价格获得一份完整报告。
- 首月页面必须同时显示折算价格、折算额度、完整月价格和次月完整额度。

### 5.3 临近月末购买

- 自动续费必须由用户主动选择，默认不选中。
- 如果首次购买距次月 1 日自动扣款不足 5 个完整日，次月不得自动扣款。
- 这种情况下，折算期结束后由用户手动确认下一完整月；确认后才进入正常自动续费。

## 6. 用量计量

### 6.1 通用要求

- 所有用量由可信服务端记录，浏览器不能直接写入用量或额度。
- 每个计量事件必须有唯一幂等标识。
- 使用记录不可覆盖，只能通过有原因、有操作者的冲正事件更正。
- 客户必须能查看已用量、预占量、剩余量和重置时间。
- 并发请求必须通过数据库原子操作校验和占用额度。

### 6.2 计数语义

- 一次用户主动提交并成功返回的查询计一次，不论结果来自缓存还是新计算。
- 双击、网络重试和相同幂等标识的重复请求只计一次。
- 分页、刷新、查看详情和重新下载已有结果不计新查询。
- 统计分析只有成功形成结果后计数。
- 导出只有文件成功生成后，按实际成功导出的行数计量。
- 有效统计订阅按当前启用的条件组合数量计量，不按发送邮件数量计量。

### 6.3 报告预占

```text
验证输入
  → 原子预占 1 份报告额度
  → 生成成功：预占转为正式消耗
  → 生成失败或取消：释放预占
```

- 自动重试沿用原任务、原订单和原预占，不重复扣量。
- 已存在的成功报告不得因重试被覆盖；新版本需要明确的版本记录。
- 单份购买生成失败时不能只恢复虚拟额度，必须按退款规则处理实际支付。

## 7. 任务池

### 7.1 平台边界

- C 用户发布需求，认证 B 机构提交申请。
- 任务可标记为 `paid`、`unpaid` 或 `negotiable`。
- 平台不参与报价、议价、付款、佣金、托管、发票或任务费用退款。
- 双方形成的服务和支付关系由双方自行约定。
- 平台仍负责处理诈骗、骚扰、违法任务、隐私泄露和平台规则违规。
- 平台条款不能排除依法不能排除的平台责任。

### 7.2 任务状态

```text
draft
  → open
  → matched_pending_consent
  → in_progress
  → completion_pending
  → completed
```

任务终止或异常状态：

- `cancelled`：发布者取消。
- `expired`：申请期限结束且无人匹配。
- `closed_unconfirmed`：B 端提交完成请求后 7 天内 C 端仍未确认或报告问题。
- `suspended`：因诈骗、骚扰、违法或隐私投诉暂停并等待审核。

申请或匹配结果另行记录：

- `withdrawn`：B 机构在匹配前撤回申请。
- `rejected`：C 用户选择其他申请或明确拒绝。
- `match_expired`：匹配后 72 小时内未完成双方联系授权；匹配记录结束，任务重新进入 `open`。

规则：

- 一个任务最多匹配一个 B 端机构。
- C 用户需要比较多个机构时，应创建独立任务。
- B 机构的申请归机构所有，并指定一个负责成员。
- B 机构可以在接受前撤回申请。
- C 用户在匹配前可以取消任务。
- B 端提交完成请求后，由 C 端确认完成或报告问题。
- B 端提交完成请求 3 天后仍无回应时提醒 C 端；第 7 天仍无回应时转为 `closed_unconfirmed`。
- 未经 C 端确认不能自动标记为 `completed`，避免虚构完成结果。

### 7.3 公开任务内容

公开任务可以包含：

- 任务类型和目的。
- 大致地区、物件类型和期望时间。
- 有偿、无偿或协商确定。
- 不含个人联系方式的任务说明。
- 申请截止时间。

公开任务不得包含：

- 姓名、邮箱、电话或证件信息。
- 精确住宅地址。
- 购房合同、房产证明、银行或收入资料。
- 能直接识别客户的附件或自由文本内容。
- 未获授权的第三方房源图片、户型图、说明、经纪人联系方式或个人信息。

V1 不在公开任务池展示客户上传的原始项目文件。

## 8. 联系邮箱双向授权

### 8.1 授权前

- C 选择一个 B 机构后，任务进入 `matched_pending_consent`，双方邮箱仍隐藏。
- 授权必须与注册协议、套餐购买和任务接受分开。
- 复选框默认不勾选。
- 双方分别看到：
  - 接收方的法定名称或姓名和联系方式；
  - 指定任务和使用目的；
  - 交换的数据类型仅为经过验证的联系邮箱；
  - 接收方所在地区；
  - 数据使用、保存、撤回、举报和权利行使方式；
  - 邮箱一旦展示，平台无法删除对方已经复制的内容。

### 8.2 完成授权

只有双方分别确认后：

1. 服务端记录任务、用户、机构、接收方、授权文本版本和授权时间。
2. C 用户、B 机构所有者和指定负责成员可以在任务详情页查看对方验证邮箱。
3. 双方收到“联系方式已交换”通知。

邮箱不得进入：

- 公开任务、搜索结果或统计页面。
- URL、客户端日志或公开错误信息。
- 数据导出和分析数据集。
- 未参与任务的机构成员视图。
- 普通管理员的默认列表。

工作人员只有在处理投诉或依法履职时才能通过受审计的受限操作访问联系信息。

### 8.3 跨地区交换

- 如果数据主体、平台处理位置或接收方位于不同司法地区，必须显示额外的跨地区接收方、处理地区和权利行使说明。
- 需要单独同意或其他跨境机制时，不能用注册时的通用同意替代。
- 对应地区的跨境机制未经法律审核前，不开放该地区组合的邮箱交换。

### 8.4 撤回与保留

- 双方完成授权前，任何一方可以撤回，邮箱不会交换。
- 匹配后 72 小时仍未完成双方授权，匹配失效，任务恢复开放。
- 邮箱交换后撤回授权时：
  - 平台停止继续展示邮箱；
  - 通知另一方停止后续使用；
  - 平台说明无法撤回对方已经保存的副本。
- 任务完成或关闭 30 天后，平台不再展示双方邮箱。
- 匹配任务、授权证据和投诉处理记录保留 3 年，然后删除或不可逆匿名化。
- 未匹配任务在取消或过期 90 天后删除或匿名化。
- 资料主体可以申请查阅、更正或删除；依法必须保留的记录仅做受限保存，不再用于撮合、分析或营销。

## 9. 自动续费、取消与支付失败

### 9.1 自动续费

- 自动续费必须主动选择，不能预先勾选。
- 结账最终确认页显示：
  - 首月折算价格和额度；
  - 下一次扣款日期、金额和币种；
  - 完整月权益；
  - 自动续费、取消和退款规则。
- 每次自动扣款前 5 天，通过站内消息和邮件提醒用户，包含金额、日期和直接取消入口。
- 不使用营销邮件同意替代交易通知；营销订阅需要独立选择和退订。

### 9.2 取消

- 用户可以在账户页随时一键取消，无需联系客服。
- 普通取消在当前已付周期结束时生效。
- 当前周期仍可使用已付权益，未用额度不结转。
- 删除应用、退出登录或停止使用不等于取消。
- 删除账户与取消订阅是独立操作；账户删除必须同时阻止未来续费。

### 9.3 续费支付失败

- 首次失败立即通知个人用户或机构所有者。
- 失败期间允许查看已有报告和账单，但暂停新的付费报告、导出和统计任务。
- 最多进行 2 次重试，每次重试前通知用户。
- 7 天内仍未成功，套餐降为 Free。
- 恢复付款后重新开通套餐，不补发失败期间未获得的额度。
- 支付失败不能删除用户已经合法保存的数据。

## 10. 退款

### 10.1 未使用退款

首次购买或每次续费扣款后 48 小时内，用户可以申请全额退款，但本计费期必须尚未使用付费权益。

“尚未使用”定义：

- C Plus：没有成功生成完整报告，也没有发送付费统计订阅结果。
- B Data Pro：没有执行 Pro 专属统计分析、导出或其他付费数据操作。
- 浏览基础页面、查看账单和账户设置不视为使用付费权益。

### 10.2 必须退款的产品规则

以下情况全额退款：

- 重复扣款。
- 未经授权的扣款。
- 扣款金额或币种错误。
- 套餐未成功开通。
- 平台确认无法交付单份报告。
- 当地强制性法律规定必须退款的其他情况。

已经使用付费权益后，普通取消不按剩余天数退款；平台错误、报告质量缺陷和强制性法律权利除外。

### 10.3 退款执行

- 批准后 3 个工作日内向原支付方式发起退款。
- 实际到账时间取决于银行或支付渠道。
- 不向其他银行卡、现金账户或第三方账户退款。
- 对应未用额度和套餐权益同时撤销。
- 财务人员必须填写退款原因并保留审计记录。

### 10.4 服务故障

- 核心付费功能因平台原因连续不可用超过 24 小时，按故障时间提供服务延期或等值额度。
- 连续 72 小时仍未恢复，用户可以终止当前周期并申请剩余期间按比例退款。
- 用户网络、第三方邮箱故障、来源暂时不可用或不可抗力，按实际影响提供延期或替代方案，不自动认定为平台故障。

## 11. 报告失败与质量问题

- 付款前尽可能验证文件格式、必填资料和支持范围。
- 仅对暂时性错误自动重试，首次执行后最多再重试 2 次。
- 重试使用同一任务、订单和预占，不重复扣费。
- 最终失败时：
  - 套餐额度自动恢复；
  - 单份购买自动原路退款；
  - 用户收到不含内部异常、源载荷或敏感信息的失败说明。
- 报告损坏、物件识别错误、承诺章节缺失或来源明显错配，免费重新生成一次；仍无法修复则恢复额度或退款。
- 用户应在交付后 7 天内提出质量问题；强制性法律权利不受该期限限制。
- 单纯不认同风险判断、模型估算或投资结论不构成自动退款理由。
- 来源错误、计算错误和数据错配必须接受纠正申请。
- 报告必须显示数据来源、时间、数据类别、模型版本和限制，不得承诺收益或替代法律、税务和专业尽调意见。

## 12. 价格和额度调整

- 价格使用不可变的版本化记录，不能覆盖历史订单或旧价格。
- 财务人员创建价格草案，超级管理员批准并设置未来生效时间。
- 涨价、额度减少、席位减少或付费功能移除均为重大不利变更：
  - 至少提前 30 天通知；
  - 展示新旧价格和权益；
  - 要求用户重新确认；
  - 未确认则在旧计费期结束后停止续费，不得静默按新价格扣款。
- 降价或增加权益可以在下一周期自动生效，并通知用户。
- 已付款周期中途不能改变价格或额度，也不能追溯收费。
- 临时额度只增加权益，不改变订阅价格或历史用量。

## 13. 内部后台角色

| 角色 | 主要权限 | 明确禁止 |
| --- | --- | --- |
| 会员运营 | 账户状态、套餐查询、客服记录 | 改价格、审核数据、查看无关客户资料 |
| 数据运维 | 授权数据采集、标准化、纠错 | 审核自己提交的数据、改账单 |
| 任务调度 | 任务暂停、派单支持、违规处理 | 默认查看客户邮箱、改价格或退款 |
| 审核人员 | 批准或驳回数据和报告 | 修改原始数据、改账单或角色 |
| 财务人员 | 订单、退款、价格草案、对账 | 查看无关报告和项目文件、授予后台角色 |
| 超级管理员 | 角色分配、价格批准、应急配置 | 作为日常运营账号使用 |

要求：

- 一人可以拥有多个内部角色，但权限逐项授予，不使用一个万能“管理员”布尔值。
- 数据运维不能批准自己提交的变更。
- 价格调整采用财务起草、超级管理员批准的双人流程。
- 超级管理员启用强认证、近期认证和完整审计。
- 后台角色、套餐、额度、退款、任务、隐私授权和价格变更全部写入结构化审计日志。
- 日志不得包含完整邮箱、令牌、支付凭证、源载荷或公开异常堆栈。

## 14. 概念数据边界

本规格不直接确定最终表名或迁移历史，但实现必须形成以下独立边界：

- 身份与机构：用户、机构、机构成员。
- 产品与价格：产品、版本化本地价格、价格生效区间。
- 订阅与权益：订阅、计费周期、权益定义、周期额度。
- 用量：幂等使用事件、额度预占、冲正事件。
- 任务：任务、机构申请、匹配、状态历史。
- 隐私：联系授权、实际披露记录、撤回记录。
- 财务：支付订单、退款、支付事件去重。
- 后台：角色分配和审计事件。

所有会员等级、额度、任务状态、所有权、机构归属、退款和价格字段均由可信服务端管理。浏览器不能直接写这些字段。

## 15. 现有架构约束

当前 Supabase 直连、Edge Function、FastAPI 和本地 worker 是相互竞争的执行路径。本设计不授权同时扩展这些路径。

实施前必须先完成一个独立的权威后端与迁移所有权 ADR，选择：

- 唯一的认证和授权入口；
- 唯一的订阅、权益和用量写入路径；
- 唯一的任务与隐私授权写入路径；
- 唯一的数据库迁移历史；
- 支付 webhook 和后台 worker 的可信执行边界。

在该 ADR 获批前，只能进行不写入真实会员、支付、任务和联系信息的静态原型或测试夹具工作。

## 16. 实施分解

本设计不得作为一次大补丁实施。按以下顺序拆分：

1. **权威后端与 schema 所有权 ADR：** 选择唯一服务端和迁移路径，不添加业务功能。
2. **身份、机构和服务端权限基础：** 机构、5 人席位、owner/member、内部角色和所有权测试。
3. **产品、价格、权益和原子用量：** 价格版本、自然月、首月折算、额度、预占和使用面板。
4. **支付、续费、取消和退款：** 结账、webhook 去重、续费提醒、支付失败、退款和价格迁移。
5. **任务池和合作方认证：** 任务、申请、一对一匹配、状态历史和违规处理。
6. **邮箱双向授权和跨地区门槛：** 独立同意、72 小时超时、受限展示、撤回、保留和跨地区开关。
7. **运营后台和审计：** 会员、数据、任务、审核、财务和超级管理员的最小权限界面。

每个子项目都需要自己的设计核对、前向迁移、回滚或 forward-fix 方案、聚焦测试和上线验证。

## 17. 验证要求

### 17.1 权限

- 匿名用户、C 用户、B Free 成员、B Pro 成员、其他机构成员、合作方、各后台角色和服务账号分别测试。
- 用户不能读取其他用户的报告、额度、退款、任务或联系授权。
- 一个机构不能读取另一个机构的成员、用量、任务申请或客户邮箱。
- 普通机构成员不能邀请第 6 个活跃成员或修改账单。
- 购买套餐不能获得合作方资格或后台角色。

### 17.2 计量

- 并发生成报告只允许一个请求占用最后一份额度。
- 双击、重试、webhook 重放和 worker 重启不会重复扣量或退款。
- 失败、取消和超时正确释放预占。
- 分页、刷新和查看已有结果不新增用量。
- B 机构 5 个成员共享同一额度。
- 月份长度、闰年、月末购买、UTC+8 边界和首月最低收费均有确定性测试。

### 17.3 订阅与退款

- 自动续费默认关闭，结账明确展示下一次扣款。
- 首次购买距月末不足 5 日时不会自动续费。
- 续费前 5 日提醒包含金额、日期和取消入口。
- 取消后不再产生下一期费用。
- 48 小时未使用退款和已使用拒绝路径分别测试。
- 重复扣款、错误币种、套餐未开通和报告最终失败触发正确退款。
- 价格上涨或额度减少未获重新确认时不会扣新价格。

### 17.4 任务与隐私

- 未匹配用户看不到邮箱和原始项目文件。
- 只有双方分别同意后才披露邮箱。
- 一方撤回或 72 小时超时不会披露邮箱。
- 非任务负责成员和普通管理员看不到邮箱。
- 公开任务文本阻止或审核个人联系方式、精确地址和敏感附件。
- 不同地区组合只有在相应合规开关启用后才允许交换联系信息。
- 关闭 30 天后的邮箱展示、90 天未匹配任务处理和 3 年审计记录处理符合保留规则。

### 17.5 数据质量与呈现

- 每个报告和统计结果显示数据类别、来源、期间、样本量、更新时间、单位、聚合方法和限制。
- 估算值和合成夹具不能呈现为核实事实。
- 列表与成交指标不能混合。
- 用户界面包含加载、空、错误、额度不足、支付失败、退款中和部分数据状态。

## 18. 首发和评估

### 18.1 推广顺序

1. 以免费预览和单份风险筛查报告作为 C 端主要入口。
2. 用真实复购和持续关注需求验证 C Plus，而不是只宣传“报告更便宜”。
3. B Data Pro 先向少量机构试点，突出数据来源、可追溯性和节省整理时间。
4. 合作方任务池保持邀请制，完成认证、匹配、投诉和隐私流程验证后再扩大。

### 18.2 核心指标

C 端：

- 免费预览到单份报告的转化率。
- 报告成功率、平均生成时间、退款率和质量申诉率。
- 30／60 日复购率、C Plus 使用率和续订率。

B 端：

- 机构开通率、活跃机构数和活跃席位数。
- 查询、分析、订阅和导出使用分布。
- 额度触顶率、支持请求和续订率。

任务池：

- 申请到匹配率、匹配耗时和授权完成率。
- 完成确认率、`closed_unconfirmed` 比例和投诉率。
- 未授权联系信息访问事件必须为零。

质量护栏：

- 数据来源和授权缺失率。
- 过期来源、异常数值、重复记录和维度不兼容数量。
- 隐私、跨机构访问和支付重复处理事故数量。
