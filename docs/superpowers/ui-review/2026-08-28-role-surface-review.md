# 三角色前端界面边界（2026-08-28）

本轮先把产品角色落实到静态网页入口，暂不把界面分层直接当作认证或数据库权限。所有新后台指标、服务任务和状态操作都属于 `synthetic_fixture` 演示，不写入数据库。

## 角色与入口

| 角色 | 产品名称 | 主要目的 | 当前评审入口 | 信息密度 |
| --- | --- | --- | --- | --- |
| C 端用户 | 小象避坑 / `ZOUBEACON` | 提交房产资料、看免费预览和完整报告、发起陪同看房/专家分析/好房推荐 | `property-analysis.html`、`projects.html`、`project.html`、`profile.html?role=consumer` | 引导优先，留白较多 |
| B 端用户 | 小象数据 / `ZOUSEEKING` | 查询数据、看统计分析、查看查询任务并承接 C 端服务任务 | `index.html`、`data-query.html`、`analysis.html`、`mypage.html`、`profile.html` | 紧凑桌面布局 |
| 管理员 | 小象数据后台 | 维护授权采集、质量审核、发布门槛和服务派单 | `admin.html?demo=1` | 最紧凑，表格优先 |

## 跨角色关系

```text
C 端：提交需求 / 接收报告与服务
  -> B 端：查询数据 / 统计分析 / 承接服务任务
  -> 管理员：采集授权数据 / 质量审核 / 发布与审计
```

- C 端项目页回到 `index.html` 时，明确标为“回到小象数据”，表示跨产品入口，不把两个品牌混成一个角色。
- C 端项目页的账户资料使用 `profile.html?role=consumer`，同一份账户逻辑根据角色参数切换品牌和导航呈现。
- 管理员入口只放在角色评审页，不放进 B 端常规导航；前端入口隐藏不代表后端授权，后续仍需用 Auth/RLS/服务端角色校验。

## 本轮界面确认点

- C 端是否保持“先提交、再确认、先看预览”的主路径，以及报告和服务任务是否属于同一项目空间。
- B 端查询、统计分析、服务任务是否应该共用一个工作台，还是拆为数据和服务两个顶级模块。
- B 端的“接单”是个人承接、团队派单，还是只负责查看并转交给管理员。
- 管理员的采集任务、质量审核、发布检查和 C 端派单是否覆盖了第一版工作人员工作流。
- 电脑端紧凑字号是否可读，`390x844` 手机端导航、按钮和表格是否仍便于触控。

确认以上界面关系后，再反查 API、Supabase 表和 migration；在确认前不新增角色字段、任务状态字段或权限策略。
