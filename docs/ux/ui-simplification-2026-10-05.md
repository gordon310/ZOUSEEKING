# 用户路径简化验收

本次实施已确认的 UX Audit Phase 2 范围：首屏目的与主操作、查询信息架构、登录回跳、物件资料步骤、项目承接和状态说明。

## 行为变化

- 数据页先显示用途和操作，再显示账户表单；月度区域报告与季度成交统计通过原生单选项切换。
- 登录、注册自动登录后返回合法的站内任务路径；报告标识和查询类型保留，外站与管理页回跳被拒绝。
- 物件资料收拢为提交、确认、检查与保存三步；可选附件默认折叠，填写进度与报告生成进度分别说明。
- 我的项目显示最近查询与报告任务。真实项目入口读取已保存资料或本人查询，报告生成使用既有 API，失败可重新生成。
- 读取失败与空列表分别呈现；退出登录立即清除项目内容，过期请求不能重新显示旧账户数据。
- 最近任务列表未命中不能证明资源不存在；带报告标识的旧项目仍可进入报告页，由既有报告权限检查决定访问。

## 验证命令

```bash
npm run build:web-assets
npm run check:web-assets
node tests/unit/auth-return.test.cjs
npx playwright test --project=chromium --workers=2
git diff --check
```

浏览器接口行为使用测试夹具验证；不构成生产 API、生产权限或部署验收。另人工查看了 390px 手机数据首页、查询页及 1280px 物件分析页。

## 明确边界

已保存物件资料的编辑、继续上传和完整历史物件列表缺少当前接口支持，本次没有新增数据库或后端路径，也没有以演示状态代替真实功能。真实页面仅提供现有读取、生成和报告查看能力，并说明资料修改尚未开放。

统计口径、额度、权限和保存确认保持既有合同。未部署或修改生产环境。

最终验证结果：Chromium 浏览器套件 136 passed；登录回跳安全检查通过；生成资源一致性与 git diff --check 通过。
